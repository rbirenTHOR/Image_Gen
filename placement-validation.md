# Composition placement update

Composition batches analyze the RV and selected landscape together once, then persist four independently directed shots before parallel fal submission. Every shot has a human-readable label and a complete prompt that specifies feasible ground, approximate position/scale, supported orientation, and preservation constraints. Explicit user directions override default shot archetypes. Failed planning submits no image-generation requests; failed image retries reuse the persisted prompt. Existing batches and image assets retain their saved history.

Validation: nine unit tests passed; the 60-case desktop/mobile/light/dark journey suite passed. Six focused placement and large-reference cases passed after reference-transfer changes, covering planner failure, four different outbound Max prompts, two high-detail vision references, stable retries, duplicate request recovery, labels after reload, large-file optimization and cached reuse. Automated generation responses are fixtures.

A separate real fal batch produced four 3840 × 2160 photographs. Visual inspection confirmed left-side, right-side, closer foreground and farther down-road placements. One interrupted result transfer recovered by retrying saving without generating again. Generated framing and dimensions are approximate, and RV geometry/background preservation still require image review.

The real test also exposed fal image-input rejection above 25,000,000 bytes. References above that threshold now use the documented fal workflow-utilities/compress-image utility at JPEG quality 90, with max_width and max_height explicitly null. This is ordinary JPEG optimization, not generative enhancement. Original files stay unchanged. Optimized reference files are size-checked, streamed through JPEG signature validation, cached, and reused. A real 32,372,794-byte, 8064 × 6048 source yielded an 8,096,616-byte reference with the same verified dimensions. References above the utility's 60 MB limit fail before generation. Original source detail is retained at the same pixel dimensions, with lossy JPEG compression; this does not make generated outputs 8K.

Schema migration 0002 adds optional-by-default shot_label and generation_prompt fields to jobs; prior migrations are unchanged. Provider utility schema verified from https://fal.ai/api/openapi/queue/openapi.json?endpoint_id=fal-ai/workflow-utilities/compress-image .

## Physical placement and selectable quantity — September 13, 2026

Generation now defaults to two images across the creation wizard and campaign chat, with a 1–4 selector. Server validation enforces integer counts; the planner, placeholder cards, jobs, progress, saved-image counts and status labels follow the requested count. Chat draft quantities survive reload. Existing batch histories derive their totals from persisted jobs. Idempotent requests reject changed quantities, including the insertion-race recovery path. The eight-active-image ceiling now considers the incoming batch size.

The previous planner forced wide-left, opposite-side, closer and farther compositions and minimum differences in position/width. Those targets are removed. Planning now prioritizes reference-camera compatibility, observed body proportions, feasible load-bearing ground, tire-contact landmarks, depth-derived scale and local shadows. It explicitly distinguishes terrain perspective from a distant mountain skyline, prohibits stretching or inventing unseen sides, and keeps distant requests distant. Clearly incompatible photos produce an actionable response without image submissions. Transient assessment failures retain the existing labeled fallback behavior, now using conservative terrain-led presets rather than fixed percentages. Image generation remains Sunburst Max via fal; the existing vision planner uses medium reasoning.

A real two-image application batch used the sample travel trailer and Margarita Lookout Dirt Road, producing two 3264 × 2448 PNGs. Both showed distinct road/shoulder placements, supported tires and jack, coherent shadows and recognizable vehicle proportions. The model made the RV larger than the approximate planned 21–24% width targets. Thus the new prompts improve the physical constraints but are not deterministic placement controls or a guarantee of exact geometry. Review remains necessary. No production campaign assets or selections were altered during this live generation test; results are in the local validation campaign.

Validation includes 13 passing domain tests, TypeScript and production build; the 25-case desktop suite passed 24 cases initially, with the remaining case corrected for its obsolete four-image saved-count expectation and verified in the focused rerun. Updated tests cover default two-image requests, all 1–4 quantities, invalid counts, exact outbound job counts, no-generation incompatible-ground handling, retries, preservation of old four-shot histories, chat quantity persistence and original media loading.

The focused 12-case desktop/mobile/light/dark run passed 11 cases; its mobile chat reload test raced page hydration and skipped switching from Gallery to Creative chat. The test now waits for the campaign composer to attach before choosing the mobile tab. The quantity and incompatibility cases passed on all three viewports, with accessibility checks passing for the tested surfaces.

Final mobile campaign rerun passed after waiting for the hidden composer DOM before selecting the visible chat tab. All identified test failures are resolved; the remaining limitations are the image model’s approximate placement and potential detail drift.
