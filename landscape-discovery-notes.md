# Landscape search and review

The new flow is available from Library → Landscapes → Find real photos and from The setting → Find real photos. Search uses Wikimedia Commons metadata with a native 8K-width default (7,680+ pixels wide, 2,160+ high), or a 4K option. Results are landscape-oriented JPG, PNG or WebP originals up to 64 MiB with a public-domain or CC0 source declaration. Tagged generated artwork, maps, paintings and aerial/satellite references are excluded. Metadata filtering does not prove authenticity or suitable RV ground space; the review screen shows the actual photograph, exact dimensions, source, photographer, original link and license before adding it.

Reviewers can give the photo a library name, classify the scenery and ground space, and retain placement notes. Add to library stores the original; Add & use backdrop also selects it in the current campaign and continues to composition. Search itself performs no image generation. Imports re-fetch source metadata by numeric Commons page ID, reject arbitrary URLs and unsupported metadata, and use deterministic owner-scoped IDs to prevent duplicates. Imported originals are streamed into private R2 before the asset is inserted. Existing shared catalog assets are reused. A new nullable-independent metadata column preserves provenance across reloads without changing existing records.

Validation: 11 domain tests passed. Discovery, existing photo-library and placement browser tests passed across desktop light, desktop dark and mobile light; the initial 18-case run found two mobile overlap failures, both fixed and verified in a four-case mobile rerun. Automated cases cover search outage/retry, pagination, resolution filters, changed licenses, unsafe URL injection, failed original import/retry, duplicate prevention, source metadata persistence, Add & use into a four-image composition, existing high-resolution reference caching and campaign chat. Axe found no violations in the tested discovery and review surfaces. TypeScript and the production build were checked separately.

Live-source verification used the actual Commons API for Alaska landscape. Eligible originals included Alaska landscape scene 19 and West Branch of the Toklat. The real Alaska panorama was imported into the local test library, then loaded from the studio media route; the browser reported native dimensions of 10,224 × 2,342. No fal generation was needed for this live import check.

Mobile refinement: setting tabs wrap at narrow widths; the selection footer is absent during discovery and does not float over the unselected landscape library. Imported 4K photos have an accurate 4K badge instead of inheriting the curated catalog's 8K label.

Source API references: https://www.mediawiki.org/wiki/API:Imageinfo and https://www.mediawiki.org/wiki/Help:CirrusSearch . Photo availability and metadata depend on Wikimedia Commons. Sparse 8K results can be broadened with 4K or a less specific place name.

## Search recovery refinement — September 13, 2026

Detailed queries now normalize common spelling errors and, when empty, retry with the place or event words. Two-word names stay together as a phrase. Removed the incomplete license-template prefilter; actual public-domain/CC0 metadata validation still applies to both search and import. Empty eligible source pages can advance once before broader wording is tried. The UI explains the matching query without changing resolution or license requirements, and pagination keeps using that successful query. Empty 8K searches offer an explicit 4K action; 4K searches no longer suggest selecting the already-active 4K setting.

The exact reported query `burning man concenrt open area` at 4K returned 37 eligible real-source photographs through the local application API after broadening to `burning man`. No images were generated or imported for this check. Validation: 12 domain tests, TypeScript, and 9 discovery browser cases passed across desktop light/dark and mobile; the final phrase-matching adjustment passed all 3 focused typo/recovery/pagination cases.
