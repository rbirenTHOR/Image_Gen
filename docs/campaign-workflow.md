# Campaign workspace

The primary workflow is **RV → Shoot setup → Deliverables → Results**. Campaigns open their last saved section. New campaigns start blank, with setup selection only in step 2.

- RV: choose an original inventory photo, upload a photo, reuse a previous campaign's original RV, or use an approved reference pack. Pack selection sends the primary RV and one supporting identity/detail image; style, interior and evaluation references are excluded from automatic identity selection. A supporting view can also be selected or uploaded explicitly in the RV step.
- Shoot setup has two paths. **Use an existing setup** chooses a Jayco recipe or copies a previous campaign’s saved scene direction. The setting, location treatment, brief, people, props and object references move together as an immutable snapshot with source provenance. The selected RV and its supporting identity references stay unchanged. The summary is read-only until **Customize this setup** creates an editable copy.
- **Create a custom setup** exposes image selection/upload/discovery, location treatment, people, props and direction. A previous campaign photograph is explicitly just a photo reference, not its entire setup. Changing the setting clears old direction, cast, props and object references and resets scene-specific shot text. Switching an existing setup does the same reset, then applies all fields from the chosen setup. Output shapes and role IDs stay intact; existing images and historical batch snapshots are preserved.
- Deliverables default to six shots for a new campaign. Selecting a preview, six-shot or 18-shot package sets the plan to those roles, instead of accumulating an unexpected number. Users can change shapes, reorder, remove or add roles. Free-form shot direction on an existing setup requires explicit customization. Use **Select all**, uncheck unwanted roles and **Generate N selected photos** once. All checked roles (up to the 30-shot plan limit) are persisted in one batch. Every selected image is submitted concurrently to the fal queue. Provider account capacity determines actual rendering concurrency; the app does not wait for earlier photos to finish. Existing ready shots selected again create new versions. Package selection itself never generates or charges.
- Results: generated photos are automatically retained as unapproved drafts, grouped by planned shot. Previous versions remain visible when the brief changes. Use Review & approve for source comparison, actual-size inspection, approval and master download. Plan a new version to regenerate one role; Reuse this setup copies the scene direction that produced an image, while keeping the currently selected RV. Edits to a planned image through chat remain grouped as versions of the original shot. Existing chat refinements and gallery tools are under Refine images & manage gallery; legacy setting/prop generation and crop/export tools remain under Advanced image tools.

## Persistence and deployment

Apply `drizzle/0007_productive_hercules.sql` before deploying the updated app. It adds workflow JSON/revision fields to projects and immutable workflow snapshots to generation batches. No existing assets, approvals, memberships or batches are deleted.

On first opening a legacy campaign, the app reconstructs the brief from its latest compose batch, preserves its selected sources, and derives its requested roles from historical jobs. If no roles exist, it starts with a six-shot campaign. Legacy persisted workflows without setup metadata remain custom and keep their original shot plans and directions. Existing photos without a complete workflow snapshot are labeled as legacy rather than counted as verified coverage of the current brief.

Updates use optimistic concurrency; another window's changes cannot silently be overwritten. Autosaves are serialized and visible in the header. Navigating through the app flushes pending edits; unsaved unloads prompt the browser. A rejected save leaves the edited form on screen.

The generation endpoint reads the saved plan, validates references against ownership, validates all selected shot IDs and enforces a 60-outstanding-request owner budget for campaigns (30 per selection), and records per-shot prompts/formats plus the full campaign snapshot before provider submission. Retries use those saved inputs. The client retains an unconfirmed generation request in session storage across reloads; Recover last request reuses its identifier and does not create a second paid batch.

The original files retain their dimensions. Native requested generation sizes are distinct from later export cropping; preview thumbnails are not delivery files.

## Full-selection generation

All new campaign jobs are persisted before being submitted together with `Promise.allSettled`. References use expiring remote URLs to avoid duplicating large base64 images across a full shoot in Worker memory. A provider failure affects only that image and is never automatically resubmitted by the app. Once accepted, fal owns the queue and execution continues if the browser closes; reopening reconciles results. Submission with an uncertain receipt still requires provider-history review before retrying. Legacy `waiting` jobs resume through atomic claims on polling, now up to the full batch size. Duplicate tabs cannot submit the same waiting job twice. The 60-outstanding-request campaign budget prevents unbounded overlapping shoots; ordinary editing retains its eight-request budget.

API validation covers an 18-role plan with two unchecked (exactly 16 provider requests), concurrent polling, replay after settings change, and a single provider rejection that leaves the other selected shots able to complete. Browser validation covers Select all, unchecking, one-click generation of five shots and reload recovery. All use simulated providers.


## Evidence-based RV viewpoints

Campaign planning now inspects every labeled reference, including the supporting RV photo and any object reference. Before image submission, it must return structured evidence for each RV photo: visible perspective, fixed landmarks, limitations and whether it supports the same unit. Each shot chooses one usable source reference and an adaptation to its requested camera role. Scene and object photos cannot supply RV geometry. Missing, invalid or unavailable assessments stop campaign generation before image charges; legacy non-campaign placement retains its conservative fallback.

A single photographed view does not establish a 3D vehicle. The final generation instructions prioritize its perspective and landmark spacing over generic camera-role instructions. Variety comes from framing, people, activities, image shapes and supported crops. Duplicate photos or detail crops do not unlock unseen sides; conflicting supporting photos cannot be chosen by the plan. This is evidence-guided generation, not a pixel-preserving compositor or a guarantee of geometric fidelity. Outputs still need visual comparison with the source before approval.

Validation includes same-source and alternate-source assignments, rejection of scene-as-RV evidence, incomplete/duplicate view evidence, a mismatched supporting view, unavailable planning with no image submissions, and 16 selected images submitted before any polling with replay protection. A browser walkthrough also removed a supporting view, selected the full 18-shot package, submitted all 18 together and verified all 18 completed. All regression image requests use simulated providers. No new paid image was generated as part of this change.


## Scene integration regression repair

The mixed-format photoshoot branch had replaced the detailed placement geometry block with a shorter product-fidelity block. The shared scene-integration contract now applies to both placement and lifestyle generation and is included in lifestyle planning. It covers depth-derived scale, compatible perspective, tire/jack contact, cast shadows, destination lighting and bounce, updated reflections, edge treatment, grain, atmospheric depth and distance-dependent sharpness. Cropped lifestyle frames do not have to show the complete RV or every ground contact. Shot and RV-view limits remain in force.

The saved campaign brief and planner assessment are each included once in the final photoshoot prompt, reducing repeated competing instructions. RV photo evidence overrides stale model/configuration descriptions in reused briefs; in place mode, the selected scene overrides inherited location descriptions. Regression tests assert integration reaches both the planner and final generation payload while preserving lifestyle framing and source-view constraints. A subsequent six-image paid browser test used the standalone Jay Flight SLX and wooded mountain field scene. All six completed with distinct native shapes and concurrent provider submissions. Visual review found more coherent lighting, grass contact and atmospheric integration, but inconsistent clothing and overly wide portrait/detail frames; this was not a controlled same-seed comparison.


## People, wardrobe and close-shot continuity

Custom setup now offers an optional **People & wardrobe reference** from a previous photo, with a thumbnail. The selected RV remains the only primary vehicle source, the setting controls location and light, and the people reference controls faces and clothing only. Explicit People & activity instructions can change clothing or omit people. Existing setups copy this reference with their other locked fields; changing the setting clears it, and changing the reference creates a new brief for output matching.

The planner writes one shared cast, wardrobe and styling description that is appended identically to every selected image prompt before concurrent submission. The cast photo is labeled separately and cannot be selected as RV view evidence. Missing continuity stops planning before image generation. Portrait and social roles now demand intimate human framing; activity details prioritize hands/materials and can omit the vehicle entirely. Wider roles retain the supported RV view and scene-integration instructions. These are generation constraints, not a guarantee of exact cast or product fidelity.

Regression coverage includes reference ordering, duplicate-role rejection, immutable replay after a reference change, setup reset/copy behavior, shared continuity in all selected prompts, and preservation of close framing when shot IDs and labels are customized. Unit tests, the focused four-test API suite, TypeScript and production build passed.

A paid six-image retest through the live workflow used the previous activity photo as the third, people-only reference. All six finished in roughly 119–149 seconds of recorded generation time, with six unique receipts; an initial unconfirmed preparation failure was recovered using the same request. Visual review found consistent white/beige shirts, trousers and caps across the set and coherent environmental integration. Portrait, detail and lunch frames still included more RV than requested, and table material did not follow the wood direction reliably. These remain unapproved drafts, and framing percentages in prompts are not deterministic constraints.

## Lifestyle campaign with selective RV presence

New plans record each deliverable as **Full RV**, **Partial RV context**, or **Lifestyle only · no RV**. The default six-shot story includes one establishing RV frame and five lifestyle frames with recognizable partial RV context. Every default role across the 18-shot catalog includes the selected RV. Vehicle-free mode remains an explicit optional choice for older/custom plans, never a campaign default. Presence and image shape can be changed in Deliverables without changing the selected setup. Legacy saved plans retain their existing instructions until explicitly edited or replaced; no migration silently reinterprets their photos.

The source campaign photo supplies setting, lighting, color and styling across the story. The planner shares cast/wardrobe continuity across all shots. For lifestyle-only images, the actual generation request excludes both primary and supporting RV identity references, retains scene/object/people references, remaps their labels and uses a separate lifestyle prompt without vehicle placement or RV viewpoint instructions. The planner receives the complete reference set to coordinate the mixed shoot; generated images receive only the references relevant to their role. No embedding index or model training is introduced.

Each job uses its immutable batch snapshot for reference routing, prompt, and retry. Changing current deliverables cannot change an already submitted image or its failed-job retry. Automated regression covers mixed six-shot routing, failure/retry after all current visibility choices change, idempotent replay, cast reference labels and old-plan compatibility. Exact vehicle geometry and cast continuity still require visual review; these remain generative outputs rather than protected-pixel composites.

The live six-shot test also exposed another preparation failure: an incomplete response followed by a timeout on the larger retry. Planning now requests low reasoning effort and concise per-shot, continuity and view-evidence prose while keeping structured validation and the same output allowance. This limits planning overhead without removing the RV evidence checks.

Paid browser validation created **Eagle — Desert Days lifestyle story** from the original standalone Eagle and the Dropbox-derived Centurion desert photo, using the existing Golden desert escape setup. After recovering the same request identifier, one batch with six unique provider receipts completed in approximately 96–152 seconds of recorded generation time. Reload retained all six outputs and their current-brief matching. All six were visually reviewed, including a source comparison for the establishing RV. The three lifestyle-only images contain no RV; activity, social and detail images have related outfits and warm desert styling across six distinct output shapes. The partial-context portrait and story still show the front cap and too much RV, and the tactile detail remains wider than requested. No output was approved. Vehicle identity is not certified by this test.

After inspecting the persisted prompts, the no-RV wording was narrowed to motor vehicles, explicitly allowing requested bicycles; that wording-only clarification passed automated checks but has not had a separate paid retest. The successful vehicle-free images already included bicycles. The next visual improvement should address partial-reference composition and tighter detail crops, rather than relaxing product fidelity or treating job completion as image acceptance. Earlier Mountain retreat drafts also showed vehicle mutation, which the initial walkthrough failed to catch. They are not an approved fidelity baseline.

Following review, the campaign requirement was clarified: the RV must be omnipresent while people and activities lead. Full/contextual defaults and the planner now require RV presence; partial roles reframe the action around a faithful source-supported RV fragment instead of omitting it. The live Desert Days plan was updated through the UI using the same Golden desert escape setup, retaining the RV, setting, people, props, six roles and image shapes. The three earlier vehicle-free frames remain historical drafts and need new versions to meet this revised plan. This change did not generate additional paid images.

Natural RV presence is distinct from product prominence: the RV stays visible in lifestyle frames as background or a supported crop, while assigned hero/product roles can lead with it. The shared view contract and planning instructions explicitly permit cropped, occluded or naturally soft logos and forbid moving, enlarging or sharpening branding to prove identity. Vehicle geometry remains fixed; composition adapts through people, activity and framing. This prompt revision affects newly generated versions, not existing images or immutable retries.
